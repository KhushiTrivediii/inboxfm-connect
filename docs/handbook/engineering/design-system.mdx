# Web Design System Contract (`packages/web`)

This document defines the formal contract for styling, tokens, UI primitives, and state handling in `packages/web` (the Inboxfm Connect developer console and dashboard).

---

## 1. CSS Custom Properties & Token Contract

The design system is token-driven and declared in `packages/web/src/styles/globals.css` using Tailwind CSS v4 `@theme inline` and CSS custom variables under `@layer base`.

## 2. Typography Scale & Spacing Rhythm

### Typography Scale
Inboxfm Connect uses a dense, tool-like information density tailored for enterprise automation workflows:

- **Font Family**: Inter, `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`.
- **Default Body**: `14px` (`text-sm`, `leading-5`). Avoid loose 16px body copy in tables and lists.
- **Secondary / Helper Text**: `12px` (`text-xs`, `leading-4`) with `text-muted-foreground`.
- **Monospace / Identifiers**: `font-mono text-xs` or `text-[11px]` (used for IDs, tokens, JSON keys, endpoints).
- **Page Titles**: `text-xl font-semibold tracking-tight` (20px).
- **Section Headers**: `text-base font-semibold tracking-tight` (16px).
- **Card / Group Headers**: `text-sm font-medium` (14px).

### Spacing Rhythm
- **Page Gutters**: `p-6` (24px) or `space-y-6`.
- **Card Padding**: `p-4` (16px) or `p-6` (24px) for major panels.
- **Form Row Gaps**: `gap-4` or `space-y-4`.
- **Button / Input Internal Padding**: `px-3 py-1.5` (`text-sm`).
- **No Negative Margins**: Never use negative margins (`-m-*`). Structure components with `flex`, `grid`, `gap`, and explicit container bounds.

## 4. State Handling & Presentation Contract

Every dashboard view must conform to the 4-state lifecycle contract:

```
[ Initial Query Fetch ] ───────────► <LoadingState> / <Skeleton>
        │
        ├─── Query Error ──────────► <ErrorState> + Toast Alert
        │
        ├─── Zero Results ─────────► <EmptyState> + Action CTA
        │
        └─── Data Available ───────► Table / Card Grid + Cursor Pagination
```

### When to use `<Skeleton>` vs `<LoadingState>`
- **`<Skeleton>`**: Use inside components for granular inline loading (e.g., table rows, card metrics) where the container layout is already known.
- **`<LoadingState>`**: Use as the fallback for whole-page route transitions (`React.Suspense`) or major view switches.

### When to use `<EmptyState>` vs `<ErrorState>`
- **`<EmptyState>`**: Use when the query was **successful** (HTTP 200) but returned an empty dataset (`items.length === 0`). Must provide a helpful description and an actionable button (`actionLabel` + `onAction`) guiding the user to create or connect the resource.
- **`<ErrorState>`**: Use when the query **failed** (HTTP 4xx/5xx or network error). Must clearly explain that a network or server issue occurred and provide a retry callback (`onRetry`) with the default button label ("Try again").

## 5. Query Error Handling Policy (`meta`)

All queries created with `@tanstack/react-query` must follow the error disclosure policy:

- **Primary Page Data Queries** (Connections, API Keys, Activity, Executions, Triggers):
  Set `meta: { showErrorToast: true }` so failure triggers a global toast notification with the error details.
- **Auxiliary Queries** (Feature flags, categories, dropdown options, tags):
  Omit `showErrorToast` and fail silently or show fallback options to avoid alert spam.
