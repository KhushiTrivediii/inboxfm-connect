<Warning>
This setup is only meant for personal use or testing. It runs on [PGLite](https://pglite.dev/) (embedded PostgreSQL) and an in-memory Redis queue, which supports only a single instance on a single machine. For production or multi-instance setups, you must use Docker Compose with PostgreSQL and Redis. You will not be able to upgrade from Community Edition to Enterprise out of the box, as Enterprise does not support PGLite.
</Warning>

To get up and running quickly with Inboxfm Connect, we will use the Inboxfm Connect Docker image. Follow these steps:

## Prerequisites

You need to have [Git](https://git-scm.com/book/en/2/Getting-Started/Installing-Git) and [Docker](https://docs.docker.com/get-docker/) installed on your machine in order to set up Inboxfm Connect via Docker.

## Install

### Build the Image and Run the Docker image

Build the unified image from this repository — the same image `docker-compose.yml` builds and runs — and start a single container with the embedded PGLite database and the in-memory queue:

```bash
git clone https://github.com/Mihir-Rabari/inboxfm-connect.git
cd inboxfm-connect
docker build -t inboxfm-connect:local .
docker run -d -p 8080:80 -v ~/.activepieces:/root/.activepieces -e AP_REDIS_TYPE=MEMORY -e AP_DB_TYPE=PGLITE -e AP_FRONTEND_URL="http://localhost:8080" --name inboxfm-connect inboxfm-connect:local
```

### Configure Webhook URL (Important for Triggers, Optional If you have public IP)

**Note:** By default, Inboxfm Connect will try to use your public IP for webhooks. If you are self-hosting on a personal machine, you must configure the frontend URL so that the webhook is accessible from the internet.

**Optional:** The easiest way to expose your webhook URL on localhost is by using a service like ngrok. However, it is not suitable for production use.

1. Install ngrok
2. Run the following command:
```bash
ngrok http 8080
```
3. Replace `AP_FRONTEND_URL` environment variable in the command line above.

## Upgrade 

Please follow the steps below:

### Step 1: Back Up Your Data (Recommended)

Before proceeding with the upgrade, it is always a good practice to back up your Inboxfm Connect data to avoid any potential data loss during the update process.

1. **Stop the Current Inboxfm Connect Container:** If your Inboxfm Connect container is running, stop it using the following command:
   ```bash
   docker stop activepieces_container_name
   ```

2. **Backup Inboxfm Connect Data Directory:** By default, Inboxfm Connect data is stored in the `~/.activepieces` directory on your host machine. Create a backup of this directory to a safe location using the following command:
   ```bash
   cp -r ~/.activepieces ~/.activepieces_backup
   ```

### Step 2: Update the Docker Image

1. **Pull the Latest Source and Rebuild the Image:** Run the following commands in your clone of this repository to rebuild the unified image from the new version:
   ```bash
   git pull
   docker build -t inboxfm-connect:local .
   ```

### Step 3: Remove the Existing Inboxfm Connect Container

1. **Stop and Remove the Current Inboxfm Connect Container:** If your Inboxfm Connect container is running, stop and remove it using the following commands:
   ```bash
   docker stop activepieces_container_name
   docker rm activepieces_container_name
   ```

### Step 4: Run the Updated Inboxfm Connect Container

Now, run the updated Inboxfm Connect container with the latest image using the same command you used during the initial setup. Be sure to replace `activepieces_container_name` with the desired name for your new container.

```bash
docker run -d -p 8080:80 -v ~/.activepieces:/root/.activepieces -e AP_REDIS_TYPE=MEMORY -e AP_DB_TYPE=PGLITE -e AP_FRONTEND_URL="http://localhost:8080" --name activepieces_container_name inboxfm-connect:local
```


Congratulations! You have successfully upgraded your Inboxfm Connect Docker deployment
