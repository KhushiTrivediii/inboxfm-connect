Inboxfm Connect is building a self-hostable integration layer for applications and AI agents. Your product authenticates its customers and owns their experience. Connect supplies the account connection, integration discovery, and action execution infrastructure.

It is an independent fork of [Activepieces](https://github.com/activepieces/activepieces), with an inherited TypeScript integration catalog and a headless runtime. The dashboard is an operator console for integrations, connections, API keys, and MCP configuration.

## The customer journey

1. Your customer signs into your application.
2. Your trusted backend creates a short-lived Connect session for that customer's `externalUserId` and allowed integrations.
3. The customer opens the returned connection URL and authorizes their third-party account.
4. Your backend discovers a tool and executes it using that customer's connection.
5. Your application presents the result and handles errors, reconnect, and revocation.

Keep project API keys on your backend. Derive customer identity from your authenticated session rather than accepting an arbitrary user ID from the browser. For OAuth providers, configure your own provider application, callback URL, permissions, and required approvals.

## Development preview

The repository contains Connect API keys, external-user sessions, operator-configured OAuth apps, connection infrastructure, prebuilt action execution, a TypeScript SDK implementation, and project MCP support. Public SDK availability, a verified external-customer OAuth journey, delegated per-user MCP access, and a general credential-aware API proxy are separate delivery gates.

The source retains MIT and restricted Enterprise material. Read [LICENSING.md](https://github.com/Mihir-Rabari/inboxfm-connect/blob/dev/LICENSING.md) before deployment or redistribution. Existing edition flags and passing tests do not grant extra rights. The planned Community dependency cleanup is tracked in [#25](https://github.com/Mihir-Rabari/inboxfm-connect/issues/25).

Some inherited reference pages still describe upstream workflows or edition features. The fork's dashboard does not include the upstream visual flow builder; use the current [architecture guide](https://github.com/Mihir-Rabari/inboxfm-connect/blob/dev/ARCHITECTURE.md) and [roadmap](https://github.com/Mihir-Rabari/inboxfm-connect/issues/63) when deciding what to build.
